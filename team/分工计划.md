# Shopping Copilot — 前期分工计划（v0.1 讨论稿）

> 5 人组。模块编号对应 [SPEC.md](SPEC.md) §4。人名先用 A–E 占位，开会时认领。
> 原则：**按模块垂直分工 + 接口先冻结 + 每日两次集成**，把"各人代码合不到一起"这个最大风险在结构上消掉。

| 人 | 模块 | 职责概要 | 主要产出 |

## 2. Day 0 —— 所有人相同的启动任务（开会前完成）

每个人独立完成，这是后面一切的地基：

1. 读完 [problem-statement.md](problem-statement.md) 和 [SPEC.md](SPEC.md)（重点 §2 评测机制）。
2. 克隆官方仓库，从 [Release 页](https://github.com/TechJam2026/techjam-conversational-search/releases/tag/participant-kit) 下载 `catalog.jsonl.gz`，校验 SHA256，解压到 `data/`。
3. 本地跑通 `python3 -m evaluator.local_evaluator`（Python 3.10+，baseline 无第三方依赖），确认得到 TechnicalScore ≈ 0.107。
4. 花 30 分钟读自己模块最相关的官方源码：A/D 读 `evaluator/local_evaluator.py` 的用户模拟逻辑；B 读 `starter/agent.py`；C 读 `docs/agent_api_contract.json`；E 读 `docs/competition_specification.md` + `docs/submission_rules.md`。

## 4. 协作约定（怎么合到一起）

**仓库**
- E 建**团队私有仓库**：导入官方 kit 作为初始 commit，官方仓库加为 `upstream` remote（方便同步官方修复）；**提交截止前转公开**（Devpost 要求公开仓库）。
- 分支模型：`main` 保护，人人从 `main` 拉 `feat/<模块>-<功能>` 分支，PR 合并，**至少 1 人 review**。
- 目录即分工：`src/dialog/`(A)、`src/retrieval/`(B)、`src/ranking/`(C)、`src/memory/`(D)、`scripts/` + `tests/`(E)。各自目录内自由，跨目录改动必须打招呼。
- ⚠️ **入口壳**：官方评测器硬编码 `from starter.agent import Agent`，所以 `starter/agent.py` 只保留一层转发壳（import `src/` 里的真实实现）。A 维护，E 在 CI 里加冒烟测试守护——这个文件坏了 = 官方评测器 import 失败 = 零分。

**接口纪律**
- SPEC §5 的 `DialogState` / `retrieve()` / `rank()` / `clarify()` 签名在 Day 0 会上冻结；要改接口 → 群里喊 + 改 SPEC + 全员知悉。

**集成节奏**
- 每次 PR 合并 → 自动跑 **50 条抽样评测**（10 分钟内出分，LLM 路径打开后全量太慢）。
- 每日 **12:30 / 17:00** 两次合龙：全部 PR 入 `main`，E 跑**全量 200 sessions**，分数（总分 + 四场景分项）记入 `experiments.md`。
- 分数回退超过 0.02 → 当次合并的人负责当晚定位。

**红线（违反直接影响成绩/资格）**
- 🚫 不改 `evaluator/` 任何文件；🚫 不提交任何 API key（用 `.env` + `.gitignore`，E 在 CI 加密钥扫描）；🚫 不动 `data/public_set.jsonl` 标注；🚫 不硬编码公开集答案。
