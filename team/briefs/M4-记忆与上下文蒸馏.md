# M4 · 记忆 & 上下文蒸馏（负责人：D · 待认领）

> 把本文件 + 根目录 `AGENTS.md` 一起喂给你的 AI 编码助手。改接口先看 SPEC §5。

## 职责

把逐轮增长的原始对话压成紧凑、结构化、可直接进 prompt 的上下文，并利用官方给的用户画像。

1. **蒸馏器**：把 `DialogState.history` 蒸馏为 `state.distilled`——当前生效约束清单、已排除项（被拒推荐的共同属性）、用户表达风格；保证 prompt 长度不随轮数线性膨胀。
2. **画像注入**：解析 `user_profile`（固定 5 键：purchase_frequency / average_prior_rating / rating_style / preference_tags / summary），把 preference_tags 与 summary 转成冷启动软偏好（第 1 轮就能用，对 browsing 场景尤其重要）。
3. **跨轮策略信号**：为 A 提供"连续 N 问无新信息""用户已拒绝过哪些方向"等信号，支撑 A 换 `other` 或押注推荐的决策；EAR 式 Reflection——被拒 slate 的共同属性值降权，喂回 C 的打分。
4. **与 C 结对**：prompt 模板库归你俩共建——你定内容结构，C 定调用与缓存排布。

## 边界

- ✅ 做：蒸馏、画像、跨轮信号、prompt 内容结构。
- ❌ 不做：决策本身（A 的）、LLM 调用机制（C 的）。蒸馏优先用规则/模板实现（快、稳、免费），只在规则不够时才用 LLM 且必须有规则降级。

## 必读

`AGENTS.md` · SPEC §4-M4 · `docs/agent_api_contract.json` 的 user_profile schema · `data/public_set.jsonl`（看真实 profile 长什么样）· `evaluator/local_evaluator.py`（用户回复都是模板句，蒸馏可以按格式做）

## Day 1 任务

1. `distill(state) -> str` 骨架：约束清单 + 轮次摘要的模板化拼接。
2. profile 解析器：5 键 → 软偏好词表（给 B 加权、给 C 进 prompt）。
3. 和 C 对齐 prompt 模板的插槽结构。

## 验收

第 10 轮的 prompt 长度与第 3 轮同量级；消融证明 profile 注入对 browsing 场景 HitRate 有提升；Reflection 信号在被拒后确实改变了下一轮排序。
