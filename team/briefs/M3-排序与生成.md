# M3 · 排序 & 生成（负责人：C · 待认领）

> 把本文件 + 根目录 `AGENTS.md` 一起喂给你的 AI 编码助手。改接口先看 SPEC §5。

## 职责

把候选集变成精确的 top-10，并生成给用户看的话术。**在线/离线双路径是硬要求**（官方最终评测可能断网）。

1. **离线打分器（先做这个，它是地基）**：`rank()` 的无 LLM 路径——约束匹配数 + 检索融合分 + rating 先验的加权打分；（Day 2+）加 CPU 交叉编码器重排：ms-marco-MiniLM-L6-v2 或 FlashRank 的 ce-esci-MiniLM-L12-v2（ONNX 免 torch，亚马逊数据同域），对融合 top-50 重排，商品文本按 `brand, title, color [SEP] bullets` 拼接。
2. **LLM 精排（增强路径）**：RankGPT 式单窗口 listwise——把 top-20 候选编号 + 蒸馏上下文给 LLM，要求输出 JSON 排列；**校验返回的 ID 合法性**，非法/为空立即回落离线打分。绝不让 LLM 重排全量候选（烧钱不涨分）。
3. **话术生成**：`clarify()` 把 A 决策的 `ask_attribute` 变成自然的问句；`message` 字段的文案。
4. **LLM 客户端**：OpenAI 兼容封装，`base_url`+模型名可配置（qwen3.8-flash 主力 / deepseek-v4-flash 备用需显式关思考 / GLM-4.7-Flash 兜底）；prompt 按"缓存友好"排布（稳定内容在前、逐轮变化在后）；统计 usage tokens 上报；重试 + 超时 + 降级全内置。

## 边界

- ✅ 做：打分、重排、LLM 调用、话术、usage 统计。
- ❌ 不做：候选生成（B 的）、问什么的决策（A 的——你只负责把决策变成话）、prompt 里的上下文内容（D 供给，你消费）。

## 必读

`AGENTS.md` · SPEC §4-M3 · `docs/agent_api_contract.json`（输出格式硬约束）· `team/调研报告.md` §1（LLM 选型与用法要点）§2.4（重排选型）

## Day 1 任务

1. 离线打分器 v1（约束匹配 + 融合分），接上 `rank()` 接口。
2. LLM 客户端封装（.env 读 key、重试、降级开关 `USE_LLM=0/1`）。
3. `clarify()` v1（模板话术即可，先跑通）。

## 验收

`USE_LLM=0` 时全量评测照常出分且断网可跑；LLM 精排相对离线路径在 MRR 上有消融可证的提升；单次全量评测的 token 花费 <¥40。
