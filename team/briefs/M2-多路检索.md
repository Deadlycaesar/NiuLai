# M2 · 多路检索（负责人：B · 待认领）

> 把本文件 + 根目录 `AGENTS.md` 一起喂给你的 AI 编码助手。改接口先看 SPEC §5。

## 职责

保证目标商品进入候选集——**你的 Recall@100 是全系统天花板**，目标不在候选集里，后面排得再好都是 0。

1. **索引**：启动时把 `data/catalog.jsonl`（5 万商品）载入内存，建两套索引（各建一次）：
   - SQLite FTS5 关键词索引，bm25() 字段加权约 (title 10, store/brand 5, categories 3, features 2, details 2, description 1)；
   - 稠密向量索引：bge-small-en-v1.5 预计算 50k embedding（384 维 float32 ≈ 77MB numpy 矩阵，暴力点积每查 <50ms，不需要 faiss）。
2. **结构化过滤**：把 `DialogState.slots` 里的硬约束翻译成过滤条件——price 区间（"budget around $X" → 如 0.7X–1.3X，系数可调）、categories 匹配、details 里的 Brand/Color/Size/Material 匹配；**过滤后候选 <10 时自动放宽为软加权**，绝不返回空集。
3. **融合**：BM25 路 top-100 + 稠密路 top-100 → RRF（k=60）融合 + 动态截断。
4. **Candidate 结构**：除 parent_asin/title 外，**必须带结构化属性字段**（color、material、price、categories、brand、可提取的 size/style）——A 的信息增益策略要在这些字段上算熵，这是 A↔B 接口的核心约定。

## 边界

- ✅ 做：索引、过滤、召回、融合、Candidate 结构化。
- ❌ 不做：精排（C 的）、提问决策（A 的）。embedding 预计算脚本归你，模型权重分发方式（Release/LFS）和 E 商定。

## 必读

`AGENTS.md` · SPEC §4-M2 · `starter/agent.py`（官方 baseline 的 FTS5 用法可直接继承）· `team/调研报告.md` §2.4（选型依据与字段拼接配方）

## Day 1 任务

1. catalog 加载 + FTS5 索引（可从 baseline 抄）+ 字段加权。
2. `retrieve(state, k=100)` 接口落地：先只有 BM25 路 + 结构化过滤。
3. 单独的 Recall@100 测量脚本（200 条公开集，报告目标商品进候选集的比例）——这是你每天的 KPI。
4. （Day 2）embedding 预计算 + 稠密路 + RRF。

## 验收

Recall@100 显著高于 baseline 同口径；过滤永不返回空集；全量评测总耗时不因索引重建而爆炸（索引只建一次）。
