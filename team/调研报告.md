**三个使用要点**：
1. ⚠️ **思考模式默认开启**（effort=high）。我们的解析/排序调用必须显式关掉：`extra_body={"thinking": {"type": "disabled"}}`，否则每次调用都在为思维链付费+等延迟。
2. 前缀缓存自动生效但 V4 有滑动窗口限制：**必须完全命中已持久化的缓存前缀单元**。写 prompt 时把 system + 候选商品块放前面且逐字节稳定、把每轮变化的约束放最后；用返回的 `prompt_cache_hit_tokens` 字段验证命中率。
3. JSON 模式（`response_format={"type":"json_object"}`）官方文档自己承认"偶尔返回空内容"——每个 LLM 调用都要包一层重试 + 规则兜底（反正离线降级路径我们本来就要做）。

充值：实名认证后支付宝/微信，余额不过期可退款。❓ 最低充值额与新户赠额需登录后才能看到。

### 1.3 不差钱路线：结论可能反直觉 ✅

各家旗舰现价（✅ 实抓官方定价页，美元/1M tokens）：GPT-5.6 Sol $4/$20（促销价）、Terra $2/$12、Luna $0.20/$1.20；gpt-5-mini $0.25/$2；Claude Fable 5 $10/$50、Opus 5 $5/$25、Sonnet 5 $2/$10、Haiku 4.5 $1/$5；Gemini 3.7 Flash $0.75/$3.75（促销至 2026-12-31）、3.1 Pro Preview $2/$12。大陆访问三家都有门槛，最顺路径是 OpenRouter（支持支付宝，充值加收 ~5.5%）。

**但是**：公开的重排序研究显示，listwise 重排能力在小模型就饱和了——7B 级重排器已追平 RankGPT-4，70B→405B 无增益。**旗舰模型用在我们这个循环里是纯浪费**：单次评测 $90–225、延迟爆炸、排序质量不涨。

所以即使不差钱，正确花法也是：
- 循环主力照样用 flash/mini 档（gpt-5.6-luna、gpt-5-mini、Gemini Flash、Haiku 4.5 或国产 flash）；
- 大模型（Sonnet 5 / gpt-5.6-terra 档）只花在**一次 A/B 消融**上：换大模型重排跑一次全量，看 TechnicalScore 有没有可测的提升——大概率没有，这个结论本身还能写进报告加分；
- 澄清问题的措辞生成如果想更自然，可以单独给这一个调用用好模型（每轮只 1 次，量小）。

### 1.4 选型建议（供会上拍板）

**主力：qwen3.8-flash**（最便宜的已验证价格 + 学生券白嫖）；**备用：deepseek-v4-flash**（关思考模式，谷时跑）；**免费兜底：GLM-4.7-Flash**。三家全是 OpenAI 兼容接口——代码里写一个客户端、`base_url` + 模型名做配置切换，顺便就实现了"多提供商容灾"。**无 LLM 规则路径永远是默认代码路径**（正式评测可能断网），LLM 是可插拔增强。预算：人均 ¥100 封顶，大概率学生券就够。

## 二、"精准推中商品"的成熟方案

### 2.1 结论先行

这个问题学术界叫 **Conversational Recommendation / Interactive Product Search**，有十年积累，成熟到有公式可抄。核心是把三个决策拆开：

1. **问什么（What to Ask）**：对当前存活候选集，选"信息增益最大"的属性提问——即该属性取值分布**熵最大**（最接近把候选集对半切）的那个。这就是"二十个问题"游戏 / Akinator 的原理。约 50 行 Python，不需要 LLM，不需要训练。
2. **何时推（When to Recommend）**：候选集 ≤10 个 → 直接推（反正一板 10 个坑）；候选分数分布很尖（低熵）→ 推；只剩 1–2 轮 → 推；否则继续问。两个阈值在 200 条公开集上调，这是**性价比最高的调参旋钮**。
3. **怎么排（How to Rank）**：硬约束先做符号过滤，幸存者交给排序器出 top-10。

### 2.2 方法谱系（都验证过出处）

- **经典线**：SAUR (CIKM'18) → CRM (SIGIR'18) → **EAR (WSDM'20)** → SCPR (KDD'20) → UNICORN (SIGIR'21)。演化方向是从置信度阈值到强化学习策略，但 RL 策略的状态特征恰恰就是"候选集熵、候选集大小、对话轮数"——**我们直接把这些特征当规则用，跳过训练**。EAR 的三段式（Estimation 估计 → Action 决策 → Reflection 反思）就是我们的架构模板；它最强的非 RL 基线正是"最大熵选属性"。
- **LLM 时代**（2023–2026）：LLM 零样本对话推荐超过所有微调基线（CIKM'23），但会幻觉出不存在的商品 → **永远只让 LLM 对给定候选列表重排，绝不让它自由生成商品**。listwise 重排的标准做法是 RankGPT（EMNLP'23 杰出论文）：把候选编号塞进一个窗口，让模型输出排列。我们候选只有 30–100 个，**一个窗口就装下，连滑动窗口都不用**。
- **何时提问的最新结论**：COPE (SIGIR 2026) 实证表明**前期问属性、后期推商品**是最优阶段策略；arXiv:2509.06185 用"重排分数分布的熵"决定问还是推。
- **工业界印证**：Amazon Rufus 官方博客的架构 = 检索/排序留在专用系统，LLM 只做理解和表达——即"**策略符号化、LLM 边缘化**"，和我们的离线降级需求完美一致。

### 2.3 推荐架构（EAR 骨架 + Rufus 分工 + 我们的模拟器情报）

```
用户消息 ──► [LLM①约束解析→JSON槽位]（离线兜底：正则/关键词解析器）
                    │
        槽位状态机（累积/擦除/Reflection：被拒商品的共同属性降权）
                    │
        硬约束过滤 ──► 存活候选集 C
                    │
     ┌── |C| 大 & 有高熵属性 & 轮数充裕 ──► 问：最大加权信息增益属性
     │        （匹配的提问能套出最多2条约束 → 给属性对的联合增益加分）
     └── |C|≤10 或分数尖或剩1-2轮 ──► 推：
              FTS5-BM25(字段加权) + bge-small稠密 → RRF融合(k=60)
              → CPU交叉编码器重排 top-50 → [LLM②listwise润色 top-20→10]
                                              （离线兜底：约束匹配数+融合分+评分先验）
```

每轮至多 2 次小模型调用（解析 + 润色），完全符合成本估算；关掉 LLM 后整条链路照常出分。

### 2.4 检索与排序栈的具体选型（✅ 均核实过参数）

| 组件 | 选型 | 理由 |
|---|---|---|
| 关键词路 | SQLite **FTS5** + bm25() 字段加权 ≈ (title 10, brand 5, category 3, bullets 2, desc 1) | 官方 baseline 已在用 FTS5，零新依赖；字段加权是 ESCI 竞赛验证过的关键 trick |
| 稠密路 | **bge-small-en-v1.5**（384 维，133MB，MIT） | <150MB 里英文检索最强（MTEB 51.68）；512 token 窗口正好罩住商品文本；50k 商品 CPU 建索引约 10 分钟；矩阵仅 ~77MB，numpy 暴力点积每查 <50ms，faiss 都不用 |
| 融合 | **RRF, k=60** | 免调参的标准做法 |
| 重排 | **cross-encoder/ms-marco-MiniLM-L6-v2**（90MB，Apache-2.0），或 FlashRank 的 **ce-esci-MiniLM-L12-v2**（在亚马逊 ESCI 数据上微调过、ONNX 免 torch） | CPU 上比 bge-reranker-v2-m3 快 ~10 倍；ESCI 微调版和我们的数据同域，几乎是为这题定制的 |
| 商品文本拼接 | `brand, title, color [SEP] bullets` | ESCI 竞赛亚军配方；brand/color 缺失时从 details 回填进 title |
| LLM 润色 | 只对重排后 top-10–20 做一次 listwise（JSON 排列，校验 ID） | 交叉编码器之上 LLM 只再涨 ~1–4 个 nDCG 点，却贵 ~9 倍——所以只润色头部，绝不重排全量 |

模型分发：`HF_ENDPOINT=https://hf-mirror.com` 一次拉取（大陆可直连，✅ 验证可用），两个模型共 ~225MB，放 GitHub Release 或 LFS，正式评测零网络依赖。

### 2.5 明确不做（少走弯路）

- ❌ UNICORN 式 RL 策略训练：要图嵌入+用户模拟器+数天调 reward，收益还不比熵规则高多少（论文自己的消融说的）。
- ❌ 微调/训练任何模型：KDD Cup'24 冠军路线要 8×A100×24h 级投入。
- ❌ bge-reranker-v2-m3 / mxbai-large 上 CPU（一次评测就把时间预算烧光）、jina-reranker（CC-BY-NC 商用限制）。
- ❌ 让 LLM 重排全量候选集（烧光 token 预算换 1–4 个 nDCG 点）。
