  `rating_number` 中位数 6846 vs 全目录 12（**570 倍**）。这条轴此前完全没人碰。

### C-T3 LLM 定性实验 🔴（今夜，决定后两天走向）
实验 4b 的负收益有**两个未分离的原因**：① LLM 看不到命中证据；② 喂给它的上下文是 D 的 13 行拼接串。
**做法**：同 `--n 40 --seed 2026` 抽样，只把 prompt 上下文换成完整约束 + 逐候选命中证据，`--repeat 3` 取均值。
**验收**：无论正负都写进 experiments.md。收窄 → 方向①可投入；不动 → 彻底关闭 ①，LLM 全部转向 C-T4/C-T5。

### C-T4 改写鲁棒性 🟠（8-30，唯一能"保住 0.918"的投资）
官方 spec 原文保留了加自然语言改写的权利。当前全链路建立在逐字匹配上，一旦改写：
类目精确匹配 → 死、约束子串命中 → 死、BM25 → 半活、热度先验 → 全活。粗估 0.918 掉到 0.5 上下。
**做法**：`normalize_utterance(msg) -> 结构化约束`，规则解析优先、失败才调 LLM 兜底（离线降级红线不变）。
**先做量化**：写个改写器把公开集话术过一遍，实测掉多少分 —— 这个数字决定这项投入多少。

### C-T5 话术与 demo 🟠（8-31，人评 55% 的战场）
现状：`choose_ask()` 恒返回 `other` → `clarify()` 恒返回同一句 → **一个会话里一字不差重复四遍，全程不提商品名**。
录成 demo 视频是硬伤。`message` 不影响判分，是**唯一可以放开手脚用 LLM 的地方**（须带模板降级）。
Demo 视频按分工计划 §5 归 C 主责。

### C-T6 成本与计量披露 🟡
提交规则要求披露延迟 / token / 成本，数据源在 `llm_client.pop_usage()`。
**已知两个计量 bug**（我发现但未修，归属待定）：
1. `src/dialog/agent.py:42` 异常兜底路径返回写死的零 usage，**没调 `pop_usage()`** → 该轮 token 漏到下一轮。
2. `llm_client._usage` 是模块级全局，跨 session 共享 → 无法按 session 归因。
**卖点**：默认路径 `USE_LLM=0`、零 API 成本、200 会话 ~10 秒、断网可跑 —— 正中 Feasibility 评分项。
