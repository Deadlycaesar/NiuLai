# 团队留言板

> **这是给人和 AI 助手共用的异步讨论区。** 群里说的话 AI 看不到，commit message 又不适合来回讨论——
> 这个文件补上中间那一层：**需要别人回应、但不值得开会的事，都写这里。**
>
> ⚠️ 格式是 **v0 草案，见 T-001，欢迎直接改**。定稿前别太当真，能沟通就行。

## 怎么用（30 秒）

1. **新话题**：在文件**末尾**追加一个帖子（见下方格式）。编号顺延，撞号了随便谁改一下。
2. **回复**：在对应帖子下面加一行 `- **回复 @你的名字**：…`。不要改别人的原话。
3. **收尾**：达成一致 / 问题解决了 → **把帖子从主区移走**，在文末「已归档」里留一行结论。
   板子上永远只剩待办，一眼扫完。纯闲聊或已作废的帖子直接删掉也行，不用留。
4. **提醒别人**：帖子里 `@某人`。对方的 AI 助手读 `AGENTS.md` 时会被引到这里。

**为什么追加在末尾**：`.gitattributes` 给本文件配了 `merge=union`，两个人同时在末尾追加不会冲突。
在文件中间插入或改别人的行则可能冲突——所以只追加、不重排。

## 帖子格式

```markdown
### [T-00X] 一句话标题 · 🟡
**发起** C → **@某人**（或 @全体）　**日期** 08-30

正文。说清楚三件事：**现状是什么 / 我想让你做什么 / 不做会怎样**。
能贴数据就贴数据，别让对方去猜。

- **回复 @某人**：…
```

状态标记：🟡 待回复　⚪ 仅周知不用回　（解决了就归档，所以主区不会有 🟢）

**主区 = 待办清单**。想知道以前决定过什么，翻文末的「已归档」。

### [T-011] C-T9 结论：LLM 用来"听懂"，不要用来"排序"（三臂对照实测） · ⚪
**发起** C → **@全体**　**日期** 08-30

@陈智龙 你的 LLM_PARSE（`29a56c5`）和我的 C-T9 正好把 LLM 的两个位置各测了一遍，结论**互补且一致**：

| LLM 用在哪 | 实测 | 结论 |
|---|---|---|
| **排序**（我，C-T9） | 喂标题 → **-0.020**；喂命中证据 → **-0.0004**（3 次均值 0.9511±0.0005） | 天花板是"打平"，不是"超越" |
| **理解**（你，实验 21） | L4 无冒号改写档 **0.8330 → 0.9327** | 不可替代 |

**排序臂的关键发现**：实验 4b 的负收益**不是"LLM 不行"，是"信息饥饿"**。
把规则打分器看得见的命中证据（哪条约束在哪个候选的文案里逐字出现）原样喂给它，
负收益从 -0.020 收敛到 -0.0004。但收敛到的是**持平** —— 因为规则打分器已经把
证据里的信号提取干净了，LLM 拿到同样的证据也只能得出同样的序。

**代价**：全量 200 条 evidence 臂约 10.2 万 token、**18 分钟**，规则路径 **10 秒** ——
慢 106 倍换统计零收益。故 `USE_LLM` 保持默认 0。

**顺手修了客户端两个坑**（实验 25c）：
1. `LLM_TIMEOUT` 20s → **45s**。实测 GLM 单次调用可达 21.5s，超时后重试再失败就返回 None，
   **整轮实验静默降级到规则路径且无任何报错** —— C-T9 复跑第 2 次就是这样，tokens=0、
   分数恰好等于纯规则基线。@陈智龙 你的 LLM_PARSE 走同一个客户端，这个修复对你也生效。
2. `LLM_PROMPT` 默认 `basic` → `evidence`。basic 是已知负收益的那版，
   万一有人开了 `USE_LLM` 不该拿到它。

另核实：GLM **确实认** `thinking:{"type":"disabled"}`（不发该参数时 150 个输出 token
会全烧在思维链上、content 返回空串）。我们客户端照 DeepSeek 写的参数在 GLM 上是对的。
