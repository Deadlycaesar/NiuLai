# 团队留言板

> **这是给人和 AI 助手共用的异步讨论区。** 群里说的话 AI 看不到，commit message 又不适合来回讨论——
> 这个文件补上中间那一层：**需要别人回应、但不值得开会的事，都写这里。**
>
> ⚠️ 格式是 **v0 草案，见 T-001，欢迎直接改**。定稿前别太当真，能沟通就行。

## 怎么用（30 秒）

1. **新话题**：在文件**末尾**追加一个帖子（见下方格式）。编号顺延，撞号了随便谁改一下。
2. **回复**：在对应帖子下面加一行 `- **回复 @你的名字**：…`。不要改别人的原话。
3. **收尾**：问题解决了，把帖子标题的状态改成 🟢，**别删帖**——记录本身有价值。
4. **提醒别人**：帖子里 `@某人`。对方的 AI 助手读 `AGENTS.md` 时会被引到这里。

**为什么追加在末尾**：`.gitattributes` 给本文件配了 `merge=union`，两个人同时在末尾追加不会冲突。
在文件中间插入或改别人的行则可能冲突——所以只追加、不重排。

## 帖子格式

```markdown
### [T-00X] 一句话标题 · 🟡
**发起** C → **@某人**（或 @全体）　**日期** 08-30

正文。说清楚三件事：**现状是什么 / 我想让你做什么 / 不做会怎样**。
能贴数据就贴数据，别让对方去猜。

- **回复 @某人**：…
```

**根因**：群聊里的话 AI 助手看不到；commit message 是单向广播、没法来回；开会成本太高。缺一个**异步、AI 可读、可追溯**的层。

**我起了这个 v0，但格式该长什么样应该大家一起定。** 三个我拿不准的点：

**① 粒度：一个大文件 vs 一个话题一个文件？**
- 单文件（现在这样）：好读、好搜、`merge=union` 防冲突；但久了会很长
- 每帖一文件（`team/threads/T-001-xxx.md`）：不会膨胀、天然零冲突；但要点开才知道内容
- **我倾向单文件** —— 比赛只剩两天，帖子总量不会超过 30 个，膨胀不是问题。

**② 要不要用 GitHub Issues 而不是文件？**
- Issues 有通知、有 @提醒、能关联 commit，是正经工具
- 但 **AI 助手读不到** ——除非每次都去调 API 拉。仓库里的文件是 AI 助手 `git pull` 就能看见的
- **我倾向仓库文件** —— 我们的主要沟通对象其实是彼此的 AI 助手，就近原则。

**③ 状态怎么维护？** 现在是标题上打 🟡/🟢/⚪，靠自觉。要不要更严格（比如未解决的帖子在 `AGENTS.md` 里挂个计数）？**我倾向不要**，两天的项目别上流程。

**请直接改**：不同意就动手改这个文件，别客气。你们各自的 AI 助手也可以直接改——这就是它存在的意义。

### [T-003] `agent.py:42` usage 计量漏账 · 🟡
**发起** C → **@陈智龙**　**日期** 08-29

`src/dialog/agent.py:42` 的异常兜底路径返回写死的 `{"prompt_tokens": 0, "completion_tokens": 0}`，**没有调 `llm_client.pop_usage()`**。后果：那一轮已经累计的 token 不会被排空，会漏到下一轮、甚至下一个 session 的报告里。

另外 `llm_client._usage` 是模块级全局、跨 session 共享，所以 token 无法按 session 归因。

**为什么在意**：`docs/submission_rules.md` 要求披露延迟、token 用量和估算成本，这是 Feasibility 评分项。数据源在我的模块，但漏账点在你的文件。

**修法**（一行）：兜底路径也调 `pop_usage()`。按 session 归因是另一件事，要改成 `dict[session_id]`，可以不做。
