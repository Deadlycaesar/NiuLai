## 幕 1 · 官方基线全量跑分（33 秒）

```bash
AGENT_IMPL=baseline python3 -m evaluator.local_evaluator --output results_baseline.json
```

**预期**：`recommended_technical_score: 0.10671`，分场景 buying 0.238 / browsing 0.025 / override 0.133 / boundary 0。

**讲解词**：
- "评分 = 0.5×命中率 + 0.3×排名分 + 0.2×轮数效率。10 轮上限，只要目标商品进了某轮的 top-10 就算赢、立刻结束。"
- "官方基线 0.107。注意 browsing（用户开局只说'随便看看'）占 40%，基线在这里几乎是 0 分——这就是我们的主战场。"
- "整个评测 33 秒，改一行代码半分钟就知道涨没涨分，迭代成本极低。"

## 幕 2 · 基线是怎么死的（badcase 回放）

```bash
AGENT_IMPL=baseline python3 scripts/trace_session.py --id public_0007
```

**预期现象**（看第 1、2 轮就够）：
- 用户开场："I'm looking for Tees & Blouses Tunics, but I'm still exploring."（目标是一件 RITERA 大码上衣）
- 基线从不提问（`提问字段: None`）→ 模拟用户只回一句"这些都不太对，你问我一个具体属性吧"
- **第 2 轮 badcase 高光**：基线拿这句抱怨话本身当搜索词，top-10 变成自行车裤、万圣节袜子、束腰马甲——彻底跑偏，10 轮不命中。

**讲解词**：
- "基线三宗罪：**不记事**（上一轮聊了什么全忘）、**不提问**（用户其实很配合，问就告诉你）、**只搜当前这句话**（所以连抱怨都拿去当关键词）。"
- "看懂这个死法，就看懂了我们架构里每个模块为什么存在。"

## 幕 3 · 我们的版本全量跑分（26 秒）

```bash
python3 -m evaluator.local_evaluator
```

**预期**：`recommended_technical_score: 0.86067`，命中率 0.98、平均 2.4 轮命中；分场景 buying 0.975 / browsing 0.988 / override 0.967 / boundary 1.0。

**讲解词**（三个机制，全是人话）：
- "第一，**给 Agent 加了个记事本**：用户每轮透露的要求都记下来，检索永远用全部笔记，不是只看最后一句。"
- "第二，**每轮既提问也给推荐**：提问不花钱，推荐也不花钱，命中就直接赢——所以每轮都把当前最有把握的 10 件摆出来，同时追问一句。"
- "第三，**拿用户的原话去商品详情里找'一字不差的出现'**：这个评测的模拟用户说的要求，本来就是从目标商品详情页里复制出来的句子，找到原文出现就重重加分。"
- "还有个踩坑记录（experiments.md 第 2 行）：用户中途变卦时，我们最早把旧笔记全删了，结果变卦场景只有 0.667；后来改成'不删、只降级为次要参考'，涨到 0.967。原因：模拟用户的每条要求只说一次，删了就永远问不回来了。"

## 幕 4 · 同一条会话，我们怎么赢的

```bash
python3 scripts/trace_session.py --id public_0007
```

**预期现象**：
- 第 1 轮：按品类给出 10 件女式上衣 + 追问"还有什么要求吗"（`other`）
- 第 2 轮：用户亮出底牌 "For that, what matters is: polyester; **75% Polyester, 20% Rayon, 5% Spandex**." → 这串成分表整个目录里几乎只有目标商品的详情页有 → **第 2 轮第 1 名命中**

**讲解词**：
- "为什么追问用 `other`（'还有什么要求吗'）而不是具体问颜色问材质？读评测器源码发现：问'还有吗'是万能钥匙，用户手里任何没说过的要求都会被套出来，而且一次最多给两条。我们对比过'挑最能二分候选集的属性来问'的聪明策略（学名：熵策略），反而低 0.03 分——因为万能问法保证每问必有收获。"
- "用户吐出的成分表越长越独一无二，像指纹——这就是'原文匹配'排序为什么这么准。"

## 幕 5 · 接上大模型会更好吗？（反直觉实验）

先亮平均数（team/experiments.md 4a–4c 行）：抽样 40 条会话，规则排序 **0.882**；让 DeepSeek 对前 20 名重排后 **0.78~0.80**（跑了两轮都在这个区间）——**平均掉了约 0.1，40 条里 15 条变差**。然后现场看实例（就用幕 4 那条会话）：

```bash
USE_LLM=1 python3 scripts/trace_session.py --id public_0007
```

**预期现象**：刚才规则版第 2 轮**第 1 名**命中的同一条会话，让 LLM 重排后目标掉到**第 6 名甚至 10 名开外**（在线模型有波动，掉多少不定，但基本保不住第 1）。

**讲解词**：
- "为什么变差？LLM 只看得到标题和价格，看不到'哪条约束在哪件商品详情里原文出现了'这个指纹证据，于是凭'看起来像不像'重排——把大牌排前面，把真命天子挤下去。**精确信号被模糊判断覆盖了。**"
- "还有第二个问题：同一条会话跑两遍，LLM 给的名次可能不一样（我们已把温度参数设为 0，服务端仍有波动）——**排序不可复现，对'改一行代码看分数'的开发方式是大忌**。"
- "所以大模型开关默认是关的，纯规则路径永远是主路径（正式评测还可能断网）。让 LLM 从负收益变正收益，是 C 的核心任务，三条路线写在 experiments.md：把指纹证据喂给它 / 只在规则拿不准时才请它出场 / 让它去干排序之外更适合的活——把用户的自由表达翻译成结构化要求。"
- "成本顺带汇报：0.85 秒一次调用，整套对比实验花了不到 3 毛钱。"

## 附 1 · 预答问

- **"一直问'还有吗'是不是钻了模拟器的空子？"**——是针对性优化，但私有集用同一份评测器代码（官方声明），机制不变；通用的熵策略保留在开关里（`ASK_POLICY=entropy`），答辩时讲通用框架。
- **"公开集 0.861，私有集会怎样？"**——用户和商品都换了，会有回落；但我们没写死任何答案（红线），"记事本+追问+原文匹配"是机制性收益，应当可迁移。
- **"为什么不用 LangGraph 这类框架？"**——评测要求单文件入口+轻依赖，当前纯标准库零第三方依赖，断网也能跑。

## 附 2 · 名词小抄（讲解时用人话版）

| 黑话 | 人话 |
|---|---|
| 状态机 / 累积约束 | Agent 的**记事本**：用户每说一句就把有用信息记下来，检索永远用全部笔记。"状态机"就是"记事本 + 什么时候记/删/降级的规则"的学名 |
| 约束 | 用户提出的一条要求，如"cotton"、"预算 20 刀左右" |
| 约束逐字子串匹配 | 拿用户的**原话**去 5 万件商品的详情文本里找**一字不差的出现**。行得通是因为模拟用户的台词本来就是从目标商品详情里复制的 |
| 近乎指纹 | 上一条的比喻：像"75% Polyester, 20% Rayon, 5% Spandex"这种长串，全目录几乎只有一件商品含有——见到即认人 |
| override / 变卦 | 15% 的会话里用户第 3-4 轮会说"别管我之前说的，我要的是 X" |
| 硬擦 | 处理变卦的粗暴做法：把之前的笔记**全删**。实测丢分 |
| 已披露的约束不吐第二遍 | 模拟用户的每条底牌**只说一次**。所以笔记删了就永远问不回来——这就是硬擦丢分的原因 |
| 问中属性一次吐 2 条 | 你问的方向正好是他底牌里有的，他一口气最多给 2 条；问 `other`（"还有什么要求吗"）算万能钥匙，任何剩余底牌都算问中 |
| 熵策略 | 备选提问法："哪个属性最能把候选商品**分成两半**就问哪个"（玩二十个问题先问'是活的吗'的思路）。实测不如无脑问"还有吗"，因为后者保证每问必有收获 |
| MRR / 排名分 | 命中那轮目标排第几的得分：第 1 名=1 分、第 2 名=0.5、第 6 名≈0.17 |
| MTTC / 轮数效率 | 平均第几轮命中，越早越好；没命中按 11 轮罚 |
| 消融（实验） | 关掉某个功能再跑分，看它到底贡献了多少——experiments.md 里每行都是一次消融 |
