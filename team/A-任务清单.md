## 任务（按序执行）

### T1 修 override 降权 bug 🔴（第一位）
**问题**（已用 public_0003 复现）：override 点名的新需求（"What I need is: X"）通常在更早轮次已入槽，降权后 `_add_constraint` 遇重复值直接跳过，导致它**拿不到 hard 权重**——用户最强的信号被当成了软偏好。当前 override 分项 0.967 是侥幸，不是逻辑正确。
**改法**：`src/dialog/parser.py` override 分支——点名的 new_value 若已存在于槽位，**重新提升为 hard**（而非跳过）。
**验收**：public_0003 用 `scripts/trace_session.py` 复跑，override 点名约束为 hard；全量不回退，override 分项 ≥ 0.967。

### T2 修 override 兜底句缺口 🔴
**问题**：评测器有一句无 "What I need is" 的兜底话术（`Actually, please ignore my earlier preference.`），当前解析器识别不到，会当软约束吞掉且**不触发降权**，override 语义全丢。
**改法**：一条正则，识别该句式 → 只触发 demote、不产生垃圾槽位。
**验收**：单测该句触发降权且 slots 数不变。

### T3 取值归一化 + Slot.terms 🟠（主工作量，8-30）✅ 2026-08-29 完成
> 结果（experiments.md #6）：0.86067 逐会话零差异。对抗审查实测证明"剥离变体"在本评测器
> 卡片生成机制下零收益纯风险，terms 收敛为精确旧语义；归一化函数已收归 `src/dialog/normalize.py`，
> ranker 不再跨模块 import B 的工具。SPEC §5 的 terms 消费约定已修正（空列表 = 不参与匹配）。
**依据**：私有集的真实风险是**取值变化**不是句式变化——约束值是未清洗 Amazon 原文（180 字符上限、6% 内嵌 "; "、约 1/8 是 "Key: value" 形态）。
**改法**：
1. `Slot` 加 `terms: list[str]`（SPEC §5 已定稿）；parser 产出：内嵌 `"; "` 二次切分、`"Key: value"` 键值剥离、budget 串排除、截断尾词容错。
2. 归一化函数（`constraint_match_token` 等）从 `src/retrieval/` **收回 `src/dialog/`**；retriever/ranker 改为消费 `slot.terms`（空则回退 value），C 的 ranker 不再跨模块 import B 的工具函数。
**⚠️ 风险**：切分会改变 ranker 的"长约束加权"（碎片变短、条数变多）——必须做消融对比，回退就调权重系数。
**验收**：全量 ≥ 0.86；公开集含分号的约束（public_0014 / 0020 / 0041）用 trace_session 抽查切分正确；与 B 确认 terms 消费方式（结对点）。

### T4 稳定性硬化 🟠（8-30）
**依据**：评测器源码核实——`respond()` 异常有保护（丢一轮），但 **`reset()` 和 Agent 构造不在保护圈内**（抛异常 = 整场评测直接崩，不是记 miss）；本地评测器**没有超时逻辑**，正式评测超时可能记 miss 且本地测不出。
**改法**：`reset()` 全防御；构造函数对畸形 catalog 行容错（坏行跳过不崩）；畸形输入单测（空消息 / None profile / 超长消息）。延迟归 A 记录、README 披露（无 LLM 路径约 0.17 秒/session，无风险；LLM 路径延迟归 C 管）。
**验收**：畸形输入单测全过；人为塞坏行 catalog 能启动。
